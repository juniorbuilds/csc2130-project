Building BizTrack: A Business Management PWA from Scratch

By Toy  ·  CSC2130 – Introduction to Web Development  ·  Kibabii University

When I started this project, I wanted to solve a real problem: small business owners in my community were still tracking stock and sales using handwritten notebooks. One mistake could mean miscalculated profits, unknown stock shortages, and financial loss. BizTrack was my answer — a Progressive Web App that brings digital record keeping to any smartphone.

Why a PWA?

A Progressive Web App was the ideal choice because it combines the reach of a website with the feel of a native app. Users don't need to download anything from an app store — they simply visit the URL and can install it to their home screen in one tap. It also works offline, which is critical in areas with unreliable internet.

The Technology Stack

BizTrack was built using only core web technologies — no frameworks, no libraries, no build tools. This was a deliberate choice to keep the project lightweight and easy to understand as a learning project: 

business-pwa/
├── index.html       ← App shell
├── manifest.json    ← PWA configuration
├── sw.js            ← Service Worker (offline)
├── css/
│   ├── main.css
│   ├── components.css
│   └── animations.css
└── js/
    ├── db.js        ← Data layer
    ├── stock.js     ← Stock module
    ├── sales.js     ← Sales + profit
    └── reports.js   ← P&L reports

Profit Calculation — The Core Feature

Every sale recorded in BizTrack automatically calculates profit by comparing the selling price against the buying price stored in the stock record. The formula is simple but powerful: 

Profit per item = (Selling Price − Buying Price) × Quantity Sold
Net Profit = Total Revenue − Total Cost of Goods − Total Expenditure

This means a business owner knows instantly whether each sale is profitable, and the Reports page shows cumulative profit across daily, weekly, and monthly periods.

Challenges and Lessons Learned

The biggest challenge was implementing offline data persistence using only localStorage — since there is no backend database. Every record (stock items, sales, expenses) is stored as JSON in the browser's local storage. This works perfectly for a single-device setup, but a future version would benefit from cloud synchronisation using a service like Firebase or Supabase.

This project taught me that semantic HTML matters — not just for accessibility and SEO, but for writing code that is maintainable and readable. Using proper elements like <header>, <nav>, <main>, <article>, and <aside> made the structure of every page immediately understandable.
